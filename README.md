# AutoTargeting


### Тестирование
На данный момент есть только возможность визуального тестирования.
Для теста можно воспользоваться готовым [симулятором](https://www.tinkercad.com/things/1TxAx1QDTun/editel?returnTo=%2Fdashboard%2Fdesigns%2Fcircuits).
Для этого:
1. выполнить один из скриптов генерации данных
    1. test\python\detection\natural_logs_generator.py - генератор координат с естественным "дрожанием" рамки границ объекта для тестирования плавности движений при отслеживании или отсутствия движений, если объект не двигается относительно кадра камеры.
    2. test\python\detection\natural_logs_with_outliers.py - генератор координат с "вылетами" для тестирования плавности движения серво в случае "зашумления" картинки, когда CV-модель может ошибаться и, например, обнаруживать то, чего нет. Убеждаемся, что в таких случаях ардуино не пытается резко дергаться в сторону этих кратковременно возникающих координат.
2. копируем сгенерированные координаты и вставляем их в "Serial Monitor".

# Roadmap: Система прецизионного Pan-Tilt трекинга (YOLO + ROS2)

### 1. Внедрение динамического шага (P-Regulator)
Переход от фиксированного инкремента угла к пропорциональному управлению.
*   **Механика:** Расчет скорости поворота на основе «ошибки» (дистанции от центра кадра до объекта).
*   **Цель:** Плавное замедление при приближении к цели и быстрый рывок при резком смещении объекта.
*   **Реализация:** Вычисление дельты на стороне контроллера с использованием настраиваемого коэффициента усиления ($K_p$).

### 2. Поддержка двухосевого трекинга (2D Pan-Tilt)
Расширение системы для полноценного отслеживания объектов по горизонтали и вертикали.
*   **Hardware:** Подключение второго сервопривода (ось Y / Tilt).
*   **Software:** Модернизация структуры `CoordinatePair` и логики `processMovement` для независимой фильтрации обеих осей.

### 3. Абстракция протокола передачи данных
Вынос параметров парсера в константы и внедрение префиксных пакетов.
*   **Формат:** Переход к кадрам вида `$[PAN],[TILT]\n` (где `$` — стартовый маркер).
*   **Цель:** Повышение надежности синхронизации и легкая адаптация под разные разделители (CSV, Semicolon, Binary).

### 4. Оптимизация структуры дескриптора объекта
Переход к более компактным и информативным структурам данных.
*   **Наполнение:** Добавление параметров ширины/высоты (W, H) для оценки дистанции до объекта.
*   **Типизация:** Подготовка структуры к сериализации (Binary/Protobuf) для снижения нагрузки на CPU при парсинге строк.

### 5. Интеграция в архитектуру ROS2
Превращение Arduino-драйвера в полноценную часть графа робототехнической операционной системы.
*   **Node Abstraction:** Реализация Serial-bridge (Python-node), транслирующего данные из топиков ROS2 (`/detection_result`) в Serial-порт контроллера.
*   **Interfaces:** Соответствие стандартным интерфейсам (например, `sensor_msgs/msg/RegionOfInterest` или кастомным `msg`).
*   **Parameters:** Возможность изменения $K_p$, $Deadzone$ и $Smoothing$ «на лету» через `ros2 param set`.
